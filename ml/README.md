# WasteWise ML models

## Train all models

From the repository root, install the ML dependencies and run:

```powershell
python -m pip install -r ml/requirements.txt
python -m ml.src.train_all
```

The scripts read CSVs from `ml/data/raw/` and save fitted scikit-learn
pipelines and evaluation reports to `ml/artifacts/`:

- `demand_forecast.joblib` and `demand_forecast_metrics.json`
- `expiry_risk.joblib` and `expiry_risk_metrics.json`
- `food_waste.joblib` and `food_waste_metrics.json`
- `discount_recommendation.joblib` and `discount_recommendation_metrics.json`
- `model_metrics.json` (combined report)

The pipelines include their preprocessing and can be loaded with `joblib.load`.
Each trainer can also be run independently with `python -m ml.src.train_forecast`,
`python -m ml.src.train_expiry_risk`, `python -m ml.src.train_food_waste`, or
`python -m ml.src.train_discount_model`. Each accepts optional `--data` and
`--artifacts` paths.

## Evaluation and leakage controls

- Demand uses `perishable_inventory.csv`, features from calendar, previous
  sales (lags 1 and 7, plus the previous 7-day mean), product/category,
  inventory, price, and discount. It predicts same-day sales in a rolling
  one-day-ahead setup and holds out the latest 20% of dates. The comparison
  baseline is the preceding 7-day sales mean.
- Expiry risk uses `inventory_batches.csv`, excludes `expiry_risk_label`,
  `batch_id`, and the simulated post-outcome `waste_units_actual_simulated`
  from features, and holds out the latest 20% of snapshot dates.
- Food waste uses `perishable_inventory.csv` to predict the next calendar
  day's `waste_units`. Features are from the preceding date only, with
  calendar features for the target date. The raw `waste_units` target column
  is not an input. Only consecutive product-date pairs are used, with a
  chronological split on the target date. The report includes a zero-waste
  baseline because this dataset's waste target is sparse; do not assume the
  model beats this baseline.
- Discount scenarios are split by `batch_id`; the model estimates simulated
  gross margin across discount levels. **These scenarios are simulated. The
  model is a prototype, not evidence of real customer price response.**

Metrics describe the held-out samples and are not a guarantee of future
performance. Inspect the task-appropriate metric and its baseline before
deploying a model; in particular, the discount model must be validated with
real customer and sales outcomes before operational use.

The `ml/artifacts/model_metrics.json` report is regenerated by each training run.
In that run, the demand model reached MAE 3.58 (versus 4.03 for its 7-day-mean
baseline), expiry-risk ROC-AUC was 0.94, and simulated discount gross-margin
regression reached R² 0.94. The next-day food-waste model did not beat the
zero-waste baseline on MAE; waste was zero for 92.5% of the held-out rows, so
the supplied data does not support claiming reliable waste-amount forecasts.
